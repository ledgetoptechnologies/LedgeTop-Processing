# Synthetic reference crash and current Viewer bridge test

`tests.test_reference_current_bridge.CurrentBridgeTests.test_crashed_coordinator_then_current_viewer_read_no_acceptance` is an opt-in isolated fixture, not a release or custody qualification. It uses the actual reference worker, TLS result listener, coordinator `ReferenceControlAPI`, `ResultProxy`, persistent `WorkerOutbox`, and the staged Viewer `ReferenceProvider` and `handleReferenceResult` with `deliverAcceptance:false`. It checks zero acceptance POSTs in both the Viewer transport and coordinator and verifies retained synthetic input and archive bytes. The Viewer runs `withConfiguredStagingCustody`, its real SQLite migrations and staging repositories, `ingestStagingModelUnderAuthority`, and `verifyStagingModelUnderAuthority` under a separate UID and a synthetic root-owned lock/configuration. It registers one synthetic staged model output and verifies the retained archive. This lab authority does not prove physical storage fencing or authorize cleanup.

The worker's first coordinator delivery commits but receives a synthetic 503. A separate coordinator process reopens that committed store, receives the exact retry and commits/replays the existing receipt, then is SIGKILLed before replying. Another coordinator process reopens the store, the worker retries the same outbox identity and receives the exact saved receipt, and the current Viewer bridge downloads a structurally valid synthetic ZIP through the real TLS result proxy and runs the staging model importer. Its geometry, imagery and point-cloud contents are placeholders and do not establish a renderable model. Thus this test kills on **receipt replay**, not on the first receipt transaction; the independent test `test_coordinator_sigkill_after_receipt_commit_replays_once` covers the first-commit kill, without the Viewer bridge. No Viewer acceptance is delivered and the fixture never calls the driver cleanup path.

Viewer source exports must be exact immutable raw Git trees: older broker fixture commit `867dd3f26c16203b5fdceec3af1671846ffa208c`, current Viewer staged tree `a67d42c777c217686fdb8ff1f9d870501939c925`. The new test checks SHA-256 pins for identified JS dependencies and a combined digest for all 165 staged server files. These path reads follow symlinks and do not independently fence replacement of files or ancestors during verification/execution; transitive resolution and immutable export ownership are not qualified. Use only independently owned, read-only, stable exports. The old broker pins match the raw Git blobs at that commit; the current bridge pins independently match raw blobs from the approved staged tree. An initial archive-based export contained unexpected contents and was discarded; the successful run used separate `git cat-file blob` exports verified against these pins. Exports must not include unrelated/symlink paths or modify the owner's worktree. Set `VIEWER_REFERENCE_ROOT` to the old export root, `VIEWER_STAGED_ROOT` to the current export's `apps/viewer`, and `SYNTHETIC_TLS_ROOT` to a separately provisioned temporary directory with synthetic `cert.pem` and `key.pem` trusted for 127.0.0.1. Run only the named test, in a bounded isolated Linux container with Node 24 and Python 3. The tested local image was `sha256:0bb8832e2ce0cf718ae6b5419fa79501a75f303a82ff4b32200888329f7ef668`; it supplies Node 24, Python, Viewer npm dependencies, and setpriv. The successful run copied the read-only raw staged source into the isolated container and linked only its `node_modules` to this pinned image, so ESM dependencies resolved without editing the owner export. The test's `load_tests` limits module discovery, its class setup is a no-op, and per-test setup refuses inherited acceptance/cleanup methods before touching exports even when called directly on the subclass. A real unittest subprocess exercises that guard with nonexistent export paths. The original joint fixture remains a separate test module and must not be invoked for this no-ACK experiment.
