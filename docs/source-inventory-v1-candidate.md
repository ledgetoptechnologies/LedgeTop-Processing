# Provisional Viewer source inventory v1

This pure, inactive proposal is not connected to admission, transfer, Viewer,
or cleanup. The contract and Viewer signer have not been agreed. It hashes
RFC 8785 JCS bytes prefixed with ASCII `ltds-source-inventory-v1` and NUL.
It uses the separately pinned optional `rfc8785` candidate dependency; no
production image or runtime is changed.

The closed root has `protocol`, `schemaVersion`, `dataset`, `binding`,
`processing`, `retained`, and `generated`. Dataset contains `id` and
`manifestSha256`; binding contains `viewerTaskId`, `viewerAttemptId`, and the
server-owned `pipelineDigest`. Each original file descriptor contains exact
`datasetFileId`, `relativePath`, `byteSize`, `sha256`, `processingRole`, and
`contentType`. Processing and retained lists are disjoint and each sorted by
dataset file ID; together they must equal an independently authenticated,
sorted authoritative dataset file mapping on ID/path/size/hash/content type.
Viewer remains custodian of the original files in both lists. The proposed
resolved role vocabulary is `image` and `provider_input` for processing,
`gcp_source` and `administrative` for retained-only inputs; unresolved `auto`
is held. Viewer agreement on vocabulary and MIME representation is pending.

The caller must independently authenticate the authoritative dataset mapping
and bind it to the dataset ID and manifest SHA. This candidate compares the
mapping and claimed SHA, but does not recompute or authenticate Viewer's
manifest: that algorithm, trusted loader, revision/writer fence and complete
mapping must be agreed and verified before it can establish completeness.
The proposal preserves original Unicode code points and case exactly; no NFC,
case folding, or path flattening occurs in the inventory. It rejects exact path
or ID duplicates, traversal and unsafe separators. Different directories can
contain the same basename, and case or Unicode-normalization variants remain
distinct. A target filesystem must preflight its own collision/representation
rules before writing. The separate `reference_v1_names` preflight rejects
non-ASCII/unrepresentable basenames and ASCII case-insensitive collisions;
it does not provide a safe copy or file materializer.

`generated` is empty or has one attempt-specific GCP descriptor containing
`snapshotId` (exact Viewer attempt ID), `byteSize`, `sha256`, sorted unique
`sourceGcpDatasetFileIds`, sorted unique `imageDatasetFileIds`, and positive
`correspondenceCount`. Sources must resolve to retained `gcp_source` files;
image IDs must resolve to processing `image` files. The generated bytes are
bounded and their exact length and hash checked. The original Emlid CSV stays
retained. The current check does **not** parse the GCP bytes or prove that the
declared correspondence count/image mapping matches them; that and the actual
Viewer snapshot schema need agreement. Binding a digest is not an upload,
durable receipt, result or cleanup authorization.

The synthetic tests use actual Node `canonicalize@2.1.0` and Python
`rfc8785==0.1.4`, exercising exact non-ASCII spelling, case/basename behavior,
source completeness and generated byte mismatch. They do not run the actual
Viewer sender or establish cross-service interoperability.
