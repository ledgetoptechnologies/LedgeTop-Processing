# Disabled v2 binding bridge

The opt-in internal coordinator method binds a provisional Viewer envelope and budget plan to an existing claimed v1 job, its sealed reservation and matching complete v1/v2 manifest contents. It stores both digest identities and claim ownership in the queue SQLite database under one write transaction. A matching repeat returns the same binding; mismatched repeats fail. The trusted worker claim is checked using the existing claim snapshot, and new bindings stop when the admission gate is closed. The method has no HTTP route and is disabled unless explicitly constructed with the opt-in flag.

This bridge does not authenticate the Viewer envelope, authorize transfer, prove bytes on disk, reserve broker capacity or record broker charges. It inherits v1 admission size and 10,000-object limits. The v1 byte budget must exactly equal the plan budget. Expired or held claims cannot replay; after a restart, the existing queue recovery hold requires separate reconciliation. Existing and older binaries have no awareness of this new table and must not be mixed or used for downgrade without migration and fencing qualification. Storage integrity, crash recovery, schema migration and live deployment remain unqualified.

Expiry checks are observations before the insert or replay return, not proof that the commit or response happened before expiry. Any future consumer must independently revalidate expiry immediately before use and hold an expired binding. The admission barrier covers validation and hashing of up to 16 MiB of metadata, so a close may wait for that work. The current tests exercise restart preservation and queue hold, not power-loss durability or rollback to an older binary.
