# Disabled synthetic v2 TLS transfer

The fixture may explicitly attach the v2 spool to an authenticated worker API. A separate TLS-only route requires an explicit version 2 header and immutable coordinator geometry. Before reading each bounded chunk body it durably records an active permit; malformed or disconnected bodies and interrupted operations remain held. Finished chunk lookup verifies the recorded intent, receipt and bytes. The sender holds its verified node result and reads at most 1 MiB at a time. Finish returns only a v2 journal seal. A separate fixture-only promotion can produce a coordinator spool receipt and expose that verified spool to the version-aware Viewer reader; it is not Viewer custody, Viewer acceptance, a success status or cleanup authority.

A hold that arrives after admission can cause an already admitted operation to remain held; this prototype does not promise in-flight revocation. A lost in-memory permit nonce or an active permit after restart requires inspection. A finished chunk can be verified and replayed by a restarted sender. These tests cover small synthetic files and actual TLS/process boundaries only; the 1.5-GiB case remains arithmetic, not a preallocation or throughput test.

No runtime setting attaches this route: tests inject the fixture explicitly. The initial immutable worker claim does not itself carry the v2 version; a separate authenticated geometry row binds the claim and metadata. Older binaries may ignore v2 markers, so this is not an old-writer fence. Socket idle timeouts are not end-to-end filesystem or network deadlines; the listener's body semaphore bounds active body readers, not all HTTP connection threads. The version-aware Viewer reader is disabled by default and is not wired into runtime. There is no Viewer custody, cleanup, production deployment or large-data qualification.
