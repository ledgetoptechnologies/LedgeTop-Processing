# Draft immutable paged snapshot statement (inactive)

This is an unmounted synthetic verifier and a proposal under Viewer review, not an agreed contract or authorization. No runtime source loader, Viewer signer, atomic receiver, trusted coordinator epoch, durable replay ledger, or integrated evidence-page decoder is provided. The signed inspector never dispatches, fetches, stages or cleans up. The evidence-only synthetic harness stages only into its own dedicated test database and always returns held.

A closed statement contains `protocol` (`ltds-viewer-paged-source-snapshot-v1`), `schemaVersion` (1), `issuerId`, `keyId`, `snapshotId`, `principalId`, `environment`, `coordinatorAuthorityId`, `jobId`, `generation`, `submissionId`, `activationId`, `viewerTaskId`, `viewerAttemptId`, `preparedEnvelopeSha256`, `datasetId`, `datasetManifestSha256`, `pipelineDigest`, `sourcePageHashes`, `sourcePageBytes`, `sourceCount`, `selectedPageHashes`, `selectedPageBytes`, `selectedCount`, `inputManifestSha256`, `processingClosureSha256`, `gcpEvidenceVersion`, `gcpEvidencePageHashes`, `gcpEvidencePageBytes`, `gcpEvidencePageCount`, `gcpEvidenceByteCount`, `gcpEvidenceSha256`, `issuedAt`, `expiresAt`, and `signature`. It contains no `sourceRevision` or `revocationEpoch`: the statement attests an immutable snapshot, while current transfer authority/epoch is a separate future gate. Source count represents dataset source files only, never evidence chunks.

Proposed Ed25519 signature: canonical unpadded base64url over `LTDS-VIEWER-PAGED-SOURCE-SNAPSHOT-V1` + NUL + RFC 8785 JCS of all statement fields except signature. The implementation uses reference canonical JSON on this closed ASCII-key/identifier, string/hash/timestamp, nonnegative-safe-integer subset; cross-language signer integration is still needed. Statement raw bytes are <=64 KiB. Source/selected page arrays are equal length per stream and contain 1–64 pages, count 1–20,000 and at most 512 records/page. Page bytes and hashes exclude the mandatory LF; stream byte budget adds one LF per page and is <=12 MiB/stream. Actual frame sizes, counts and hashes must be verified during atomic staging, not inferred from the declaration.

For no GCP snapshot or generated GCP input, all six `gcpEvidence*` fields are null. Otherwise `gcpEvidenceVersion` is `ltds-viewer-gcp-evidence-chunks-v1`; `gcpEvidencePageHashes` and `gcpEvidencePageBytes` have the exact positive `gcpEvidencePageCount` length (2–512 including mandatory trailer), and `gcpEvidenceByteCount` is 1–16 MiB. Page JSON bytes/hashes exclude mandatory LF, page bytes <=65,535, and sum of page bytes plus one LF/page <=24 MiB. `gcpEvidenceSha256` means the full exact UTF-8 evidence_json bytes, not merely a correspondence hash; generated `gcp_list.txt` size/hash are separately bound in selected data. The verifier checks only declared structure: it cannot establish GCP presence, bytes, provenance or null-iff condition until evidence and selected frames are checked together.

Proposed evidence data frame: closed canonical JSON `{version,attemptId,evidenceSha256,index,offset,decodedByteCount,data}`; version `ltds-viewer-gcp-evidence-chunks-v1`, attempt/digest match statement, index starts 0 and increases, decoded offset is contiguous, and `data` is canonical unpadded base64url of 1–46,080 decoded bytes. A mandatory separate final trailer is closed `{version,attemptId,evidenceSha256,index,offset,totalBytes,complete}` with `complete:true`, index equal to data-frame count, and offset and totalBytes equal signed `gcpEvidenceByteCount`. Signed page hashes and byte counts include the trailer. Per-page SHA-256 domain is `ltds-viewer-gcp-evidence-frame-v1` + NUL + exact canonical page bytes excluding LF. Decoder must bound line/raw/base64 bytes before allocation, verify pins/order/offset/length/trailer and exact full evidence digest, and incrementally validate UTF-8 across chunks. Reject missing/extra/truncated/reordered/duplicate/tampered pages. An isolated bounded evidence parser and separate synthetic SQLite staging harness are implemented and tested; they are not wired to the signed inspector, Viewer, source/selection staging or a shared coordinator transaction.

The registry is independently configured by coordinator authority, principal, environment, issuer, key and purpose; raw key aliases are rejected. The inspector uses an independently configured UTC-millisecond server clock, a provisional 15-minute maximum signed TTL, up to 60 seconds future-issued skew and no expiry grace. Missing clock or independent snapshot pin holds. A signature match with matching prepared authority/owner/environment/task/attempt/envelope/generation/dataset/pipeline still returns `held/independent_epoch_and_atomic_staging_unavailable`. The snapshot-pin callback receives immutable identifiers only and is trusted in-process code, not a same-transaction authoritative loader or a sandbox. Real key lifecycle, revocation and current coordinator epoch authority do not exist here.

Before any activation, Viewer must independently compute a complete immutable source/selection/evidence snapshot in one coherent transaction; Processing must validate all exact source/selected/evidence bytes, GCP selection and custody, and independently reconstruct the processing closure from exact selected order and negotiated page partition. The existing receiver owns a separate database transaction and cannot be safely nested in the prepared-store transaction. A reviewed same-database transaction API and durable uniqueness/replay ledger must bind snapshotId, exact signed bytes and all pins globally across issuer/job/attempt. Incomplete or mismatched attempts hold and require fresh signing. A prior fully committed exact replay may be reported as prior status after signature expiry but must not grant a new activation; that status path and ledger are NOT implemented. Current authority and epoch must independently fence transfer before/during/after streaming and at commit; signing this immutable snapshot does not provide those protections.

Synthetic tests use ephemeral Ed25519 keys and real prepared-store records; no live Viewer signer, HTTP endpoint, actual 16k evidence, real source bytes, atomic integration, replay ledger, epoch authority or cleanup is tested. Every accepted inspection remains held.
