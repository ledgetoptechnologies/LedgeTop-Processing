# Viewer typed mapping candidate (inactive, untrusted)

This is a testable proposal, not an authenticated loader, Viewer contract or processing authorization. All snapshot, mapping, GCP evidence and binding values must come from an independently authenticated immutable source; the expected binding digest must be independently trusted. The function does not provide that authentication, compare real Viewer database records, inspect correspondence evidence bytes, or guarantee durable custody. It always returns `held_authenticated_snapshot_unavailable`, and nothing calls it in runtime. Inputs must be exclusively owned decoded values. There is no bounded network parser.

This separate candidate intentionally holds more than 10,000 source or selected input records and preserves current limits. It compares a captured `{sourceFiles,inputFiles}` against Viewer commit 551's selection rules: exclude `gcp_source`/`administrative`, include `auto` only for photo extensions, remove existing `gcp_list.txt` inputs when a generated snapshot exists, then photos first and non-photos after. It rejects duplicate source paths and preserves exact nested source paths; originals remain in `sourceFiles`. Its retained-source count includes all not-selected originals, not a custody receipt. Viewer source/input rows do not contain stable dataset file IDs; this proposal does not fabricate any.

Each ordered mapping entry is exactly one of:

- `{type:"dataset_file",pageObjectId,datasetFileId,relativePath,processingRole,mediaType}`. The independently supplied finalized dataset mapping must contain `{datasetFileId,relativePath,byteSize,sha256,processingRole}` for each source; all IDs and paths must be unique and the source snapshot must match that mapping exactly. Path, ID and role must match the selected source record; the independently bound source snapshot supplies size/hash.
- `{type:"attempt_generated_gcp",pageObjectId,attemptId,gcpEvidenceSha256,mediaType}`. This references a separate trusted evidence object `{attemptId,byteSize,sha256,sourcePaths,correspondenceSha256}`. Source paths must identify raw `gcp_source` entries, and supplied generated bytes must match size and SHA-256. The correspondence digest is an externally supplied commitment only: correspondence rows and source/GCP semantic correctness are not verified.

Each type has an ordered one-to-one page entry with matching ID, basename, size, hash, MIME and image/auxiliary kind. The externally pinned binding includes dataset ID/manifest digest, Viewer task and attempt, pipeline digest, principal, environment, coordinator authority, revocation epoch, and digests for the source snapshot, typed mapping, optional GCP evidence and page closure. Digests use reference-v1 canonical JSON prefixed with ASCII domains `ltds-viewer-typed-snapshot-v1`, `ltds-viewer-dataset-mapping-v1`, `ltds-viewer-typed-mapping-v1`, `ltds-viewer-gcp-evidence-v1`, or `ltds-viewer-typed-binding-v1`, each followed by NUL. These are proposed domains and not a Viewer agreement. MIME values come from the independently trusted mapping, not from Viewer `inputFiles`. UUID and safe-ID checks apply.

Before whole-object serialization, source and input entries, mapping items and GCP source paths are bounded and preflighted; generated GCP bytes are limited to 16 MiB. Full source snapshot and mapping bytes are each bounded to 8 MiB. A future implementation must independently validate actual snapshot identity, dataset correspondence, selection authority, GCP rows and retained-source custody; bind principal/task/attempt/authority/epoch atomically; fence revoked streams; and prove disk/retry/recovery limits. Cross-version/c41 source inventory completeness and >10k are not established.

The test uses synthetic stable IDs in an independently supplied test mapping; they are not recovered from provenance or asserted to exist in actual Viewer rows. The test fixture `tests/fixtures/viewer-processingProvenance-5513f92.js` is byte-exact Viewer `apps/viewer/server/processingProvenance.js` at commit `5513f92b6cf45221475a3c38347e3ca1dbf0c32d`, SHA-256 `e965ab977c00e2058e9f5ea21a658fb89b2ad1af3c24facefb3a7b030e8eb82c`. A test executes its exported `inputInventory()` on synthetic files and a synthetic GCP snapshot, then verifies selection, typed mapping and rejection cases. This is not a live Viewer, database, real GCP evidence or source-byte test.
