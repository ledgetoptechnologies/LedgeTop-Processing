# Indexed worker maintenance census

This source candidate adds an explicit indexed path to the existing owned worker maintenance controller. It does not activate updates, change the indexed schema/policy, reclaim metadata, issue custody/release receipts, renew grants or repair SQLite. Default and v1 calls keep their old result shapes and refuse every indexed namespace or marker without a concrete indexed context.

Before stopping, the controller uses the trusted host Docker CLI against its exact recipe/container to compare actual runtime device/inode/owner/mode for the configured state, scratch, gate, config directory, TLS files and config file with the host sources. The indexed helper issues this observation itself; caller-supplied JSON, a saved digest or copied context is not authority. A process-local opaque context is minted only after graceful stop and acquisition of the actual DaemonStateLock. Source inode/owner/config/policy changes hold. The config file may be atomically replaced only through the existing owned rebind path; its immutable base and containing directory identity remain bound, and the update controller verifies the exact published replacement. All other source identities remain fixed.

A resumed already-stopped updater in a new process cannot recreate that proof from its stored receipt. It holds `indexed_stopped_mapping_unproven`. This is an explicit remaining maintenance resilience gate, not a claim that stopped-container namespace mapping or maintenance recovery is complete. A future independently reviewed bounded namespace probe may address it. Synthetic tests execute real POSIX stat/bootstrap/SQLite/service operations with a synthetic Docker runner; they do not qualify a deployed host/container mapping or live update.

The stopped census verifies the exact current indexed schema and policy descriptor through the shared read-only `validate_profile_connection` seam, original canonical bootstrap intent, scratch-root exclusive claim, ledger/indexed creation receipts and final bootstrap receipt. Actual host paths are mapped explicitly to the unchanged original container binding after the runtime inode observation; config paths are not silently rewritten in stored authority. It validates the full fixed driver settings, exact claim request and original submission/object/grant/reservation/prefix/attempt closure. Terminal rows require the exact terminal scratch binding and complete original fetched-copy identity rows; success requires actual accepted result rows and receipt closure, and failure/cancellation requires the bound terminal receipt. These checks grant no source-release or cleanup authority.

Normalized table hashes stream rows in primary-key order with domain and length framing. The attempt table accepts the qualified 10,010 aggregate bound rather than the old blanket 10,000 limit, while typed per-job attempt closure and the grant's original budget still apply. All original normalized profile/claims/objects/seals/reservations/grants/quota/fetch/attempt tables and fixed driver binding enter the retained-history digest. Background polling timestamps remain excluded as before. Engine-pin history is independently fenced by the existing gate/native version/config publication procedure and is excluded from the restart-invariance digest because the owned update may legitimately advance it.

Full scans happen only during stopped census/recheck and the owned restart verification before reopening the update barrier. Health polling keeps its bounded existing service/readiness checks; no manifest scan was added to a health poll. Existing heavy-task exclusivity, unknown engine mutation holds, pending acceptance/outbox checks, actual reader-epoch closure and no-replay stop/start/config publication behavior remain in the controller.

Unknown journal sidecars hold without repair. An optional indexed recovery capsule is accepted only by the recovery owner's explicit read-only COMPLETE-capsule validator, with original bootstrap binding and actual root/driver identities. Pending, uncertain, changed or leftover copy/journal capsules hold. Its validated closed summary is included in both census and restart history; an old completed recovery is not current-job authority.

Retained job retirement, 10k unwrapped repeatability, actual 50GB transfer/processing, live updater allowlisting and cold stopped-mapping recovery remain separate qualification gates. No TTL or terminal flag releases a scratch reservation or the indexed metadata charge.

Historical transfer grants are semantically validated against their exact sealed reservation, original job/generation/environment/manifest, byte budget, nonce, token shape and complete object closure at the persisted finite fetch-clock highwater. A grant that expired after that observation remains valid historical evidence; no new grant or download capability is issued. Expiry at or before that highwater holds.

The current qualified terminal subset requires a complete fetched-input prefix for success and failure alike. A terminal reservation/grant/fetch failure with partial or absent fetched closure remains held even if its failure metadata was accepted. This conservative functional gate is not automatic retirement and does not support every possible terminal failure history.

The original independent positive lifecycle run failed safely at the synthetic fixture's three-second health deadline. An observation-only replay recorded an actual busy snapshot (unknown counts, driver lock occupied) taking 2.408 seconds; another snapshot took 3.272 seconds. A permitted stack probe later saw only actual empty snapshots and an idle driver waiting on its event, so the original failure-time lock location was not established. These failed and successful observations remain preserved. The positive lifecycle fixture now uses the existing WorkerPolicy default of 30 seconds rather than assuming that every local CLI snapshot plus retry fits three seconds. Production defaults and health gates are unchanged. A separate deterministic regression retains the three-second deadline, holds the real post-start driver lock until the controller safely holds, verifies start_pending/one issued start/closed ingress/updating node, then releases the lock and continues the same controller and operation to verified using actual idle SQL/HTTP evidence without another start. Test-only step-boundary synchronization prevents unrelated empty-worker readiness polls during those observations; no health response is fabricated. Cold new-process continuation remains unsupported and held.
