The operator must independently inspect the stopped/PID0 backend, closed ingress, readers, durable host operation and preserved data. These booleans are acknowledgments, not remote host attestation; the coordinator never performs Docker actions.

One BEGIN IMMEDIATE transaction verifies the persisted original owned schedule's node/authority/plan/target, exact current CAS, HELD-only state and no queued/running/held jobs assigned to that node. It changes HELD directly to UPDATING with a new random secret token; admission remains closed throughout. Existing begin/finish/hold/resume behavior is unchanged. The successful result must still be independently verified before existing finish can activate the node.

The recovery request, canonical digest, nonsecret receipt and secret token are committed atomically in owned_maintenance_recoveries. They return the token only while the exact recovered revision/plan/target/state and token hash remain current; after hold, finish or restart they return tokenValid:false without the token and never issue a reservation again. A further recovery requires a fresh UUID and fresh held CAS. No recovery is allowed from active, scheduled, draining or failed state.
