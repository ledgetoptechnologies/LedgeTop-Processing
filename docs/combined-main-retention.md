After independent preparation digest review, only `run_phase` may dispatch:

1. `begin`: re-read state under the operation lock; fresh owned schedule/CAS begin
   with full readback; restart=no; main ingress closed/drained; clean stop; fixed
   inactive TMP preserved and sealed outside stock autoexpiry, original unchanged.
2. `plan-cleanup`: exact updating/stopped/restart-fenced role and source rechecks;
   canonical host lock and strong observer; write only fresh M4E/Tim authorization

3. `apply-cleanup`: require that exact digest/auth/plan bytes and fresh strong
   fences. Apply only listed caches using the qualified CacheCleanup journal.
   No Todd cleanup, original/result removal or automatic operation replay.
4. `finish`: remeasure actual free space/RW/data; preserve the full backup guard;
   reuse verified TMP copy; backup/export; retained-safe child recreation/health/
   TMP/data verification; exact forward pins; ingress reopen; fresh owned finish
   CAS/readback. No automatic previous-image start or database restoration.

Wrong/consumed phases refuse before mutation. A phase error retains its intent,
marks independent inspection and uses only proven-owned fail-closed handling.

race must remain connected so it can finish. Foreign or busy reservations are not
closed, canceled or replayed by failure handling.
Preparation and the consumer both require the canonical root basename derived
from the request UUID, and the consumer requires runtime.root to equal that same
root. Reader receipts and phase intents cannot be split across two directories.
An uncertain finish does not re-POST or close a node that may already be active.
The thin CLI delegates only to these phase functions. Default execution prints a
static plan with zero source/API/Docker reads or mutations. `--prepare` needs the
reviewed qualification and two-field private inputs document (readOnlyObservers,
