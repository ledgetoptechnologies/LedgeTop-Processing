# Historical updater: enrolled legacy fence hold

The existing `ops/update_reference_coordinator.py` is a one-off reference-to-reference updater bound to exact historical predecessor container, image, source, state volume and checkpoint schema. That predecessor predates enrolled fence enforcement. Its fact and environment validators accept only the historical state/TLS mounts and configuration. It is not a general updater for PR83-enrolled coordinators, and must not be adapted by merely adding a volume or flag.

This draft makes its census report the presence of any SQLite object named `legacy_fence_requirement` before applying the old schema allowlist, and explicitly refuses such state. If an offline rollback census detects that marker or is unavailable, the updater leaves both its candidate and predecessor stopped and holds for inspection. A successful census with no marker can still follow the pre-existing content-difference retention policy. This is a point-in-time observation with trusted writer/volume exclusion; it is not a persistent authorization, a replacement for host updater control, or protection against an old binary or restored database erasing the marker.

A supported enrolled-to-enrolled updater remains to be implemented: it needs a new independently reviewed checkpoint ABI binding both images and their fence-supporting revisions, exact original volume and enrolled lock identity, required environment and mount on candidate/rollback containers, before/after readbacks, durable uncertainty handling, and safe restart/rollback rules with the existing node drains. It also needs controlled schema/census migration, single-authority ownership, systemd/Docker restart configuration and reboot/restore qualification. This branch does not enable an updater or modify live systems.
