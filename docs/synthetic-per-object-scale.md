# Synthetic per-object input layout

The disabled fixture worker now records `per-object-v1` in its input policy and creates each input slot in its own hash-named directory under the verified input root. It records the existing creation intent before creating the directory and syncs the parent directory; missing, pre-existing, or changed state is held rather than recreated. Existing flat-layout journals lack the policy marker and fail closed; there is no migration. The parent and its ancestors must remain trusted against concurrent rename/mount manipulation, consistent with the underlying slot primitive.

A bounded tmpfs test created 10,000 real one-byte synthetic slots: 20,000 marker scans examined 10,000 total entries, with peak Python RSS about 36 MiB. This is a slot-layout and bounded supervisor paging test, not 10,000 authenticated transfers, engine uploads, real photos or a 50 GB workload. The supervisor still caps jobs at 64 objects; its submission and grant paths still materialize all rows, and per-object HTTPS, fsync and SQLite overhead require further work and measurement. Input journal 64 MiB and archive 1 GiB prototype limits remain. Existing pinned cross-language harness scripts still expect the old flat layout and must be updated with new verified pins before use. No production activation is included.
