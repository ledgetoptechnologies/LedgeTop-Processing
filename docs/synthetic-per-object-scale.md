# Synthetic per-object input layout

The disabled fixture worker now records `per-object-v1` in its input policy and creates each input slot in its own hash-named directory under the verified input root. It records the existing creation intent before creating the directory and syncs the parent directory; missing, pre-existing, or changed state is held rather than recreated. Existing flat-layout journals lack the policy marker and fail closed; there is no migration. The parent and its ancestors must remain trusted against concurrent rename/mount manipulation, consistent with the underlying slot primitive.

A bounded test run using Docker `--tmpfs` (filesystem type not independently checked inside the fixture) created 10,000 real one-byte synthetic slots: 20,000 marker scans examined 10,000 total entries, with peak Python RSS about 36 MiB. This is a slot-layout and bounded supervisor paging test, not 10,000 authenticated transfers, engine uploads, real photos or a 50 GB workload. The supervisor still caps jobs at 64 objects; grant and submission now traverse MAC-checked metadata pages of at most 100 rows, while per-object HTTPS, fsync and SQLite overhead require further work and measurement. Input journal 64 MiB and archive 1 GiB prototype limits remain. Existing pinned cross-language harness scripts still expect the old flat layout and must be updated with new verified pins before use. No production activation is included.

A separate test verified 10,000 synthetic metadata records (including 1,000 auxiliary entries) in a fresh subprocess using the incremental inventory digest and bounded pager. The SQLite file was 4,956,160 bytes and peak subprocess RSS was about 36 MiB for that particular short-name dataset; a later-page metadata mutation was rejected. These figures are not a worst-case 64-MiB journal sizing guarantee, and the restart exercised metadata paging rather than resuming a 10,000-object transfer. The 64-object cap remains because no full 10,000-input TLS transfer, engine submission, recovery, or resource qualification has passed.

The disabled supervisor accepts an explicit fixture-only scale policy of at most 10,000 objects and 64 MiB total synthetic input. It binds that policy into the input journal and checks authenticated count/bytes, a conservative metadata planning allowance, and currently observed free blocks/inodes before fetching. Those checks are snapshots and estimates, not reserved space or a worst-case journal proof; per-object allocation and the existing 64-MiB journal guard remain mandatory. Without that explicit policy the existing 64-object ceiling remains. A 66-object authenticated TLS/fake-engine run completed locally in 2.48 seconds excluding fixture setup; this short run does not establish 10,000-object throughput or any 50-GB capability.
