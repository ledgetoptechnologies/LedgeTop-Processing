# Synthetic node capacity service

This is an explicitly enabled **synthetic-only**, loopback HTTP prototype using the existing ScratchLedger. It is not installed, connected to Viewer, or usable as a production authorization service. The adapter passes the ledger's `worker_ready` flag as an assumption; it does not observe worker readiness. Its configured directory and inode are checked locally, but this does not establish that the directory is the actual NodeODM writable mount. In particular the current cluster NodeODM uses its container writable layer, not an independently verified shared mount.

The service reserves input bytes plus a configured output budget after subtracting outstanding ledger holds and a safety floor. A one-shot start transition rechecks capacity and expiry under the ledger transaction; a repeated start or lost response holds instead of granting another start. A reservation marked started survives expiry and restart. No release endpoint is provided. The sampled free space and budget are accounting estimates, not a physical disk allocation or a bound on unknown ODM expansion. Other writers or a second ledger on the same filesystem can invalidate the estimate.

Before real use, establish the actual engine filesystem and mount identity, exclusive ownership of the per-filesystem ledger, authenticated node/worker/claim and coordinator epoch binding, a protected cross-host transport, and a fence preventing direct engine bypass. Define durable recovery and verified release after engine completion, plus expiry and lost-response semantics. Time can pass after any check and before a client acts. A single-threaded server also allows a slow client to delay service until its socket timeout. This prototype deliberately provides none of those production guarantees and does not change Viewer routing or its input cap.
