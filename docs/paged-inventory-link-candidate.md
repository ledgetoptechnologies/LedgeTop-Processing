# Paged source inventory link candidate (held)

This is a synthetic linkage design, not authentication or an admission path. It is not mounted and cannot dispatch, fetch, acknowledge or clean up. Caller must independently authenticate and validate a complete immutable Viewer source inventory and trust all binding fields, own supplied objects exclusively for the call, and retain the source inventory and custody records. Even matching inputs return `held_source_authority_unverified`. Do not use request-supplied claims as authoritative inputs. The underlying in-memory inputs are not bounded streaming/network parsers.

The trusted binding has exactly `datasetId`, `datasetManifestSha256`, `inventorySha256`, `mappingSha256`, `closureSha256`, `principalId`, `environment`, `authorityId`, `viewerTaskId`, `viewerAttemptId`, `pipelineDigest`, and `revocationEpoch`. Dataset ID/manifest and task/attempt/pipeline must equal inventory fields. The other identities and revocation epoch must be authenticated and fenced by the future trusted loader; this checker cannot establish them.

For the provisional c41d468 v1 inventory wire shape, inventory digest is SHA-256 of ASCII `ltds-source-inventory-v1`, NUL and RFC 8785 JCS of the exact inventory; `rfc8785==0.1.4` is required. The separate ordered mapping contains entries `{pageObjectId,datasetFileId}` and its pin is SHA-256 of ASCII `ltds-paged-inventory-mapping-v1`, NUL, then reference-v1 canonical JSON of the list. It must be independently bound to the trusted attempt, not supplied by the submitter as its own authority. The closure pin is the separate page-candidate closure digest. Page order, mapping order and inventory `processing` order must match exactly; processing IDs must be sorted and unique. Each page object's basename, size, digest, kind and MIME must agree with the original inventory descriptor, and page IDs and source IDs form a one-to-one map. Exact nested paths, roles, retained originals and their custody remain in the hashed inventory rather than in the basename index. The link pin is SHA-256 of ASCII `ltds-paged-inventory-link-v1`, NUL, and reference-v1 canonical JSON of the entire binding. The caller must independently authenticate this pin and obtain all binding fields from a trusted source. It commits the inventory, mapping and closure together along with dataset, caller, environment, coordinator authority, task, attempt, pipeline and current revocation epoch; hashing alone does not authorize them.

Current c41d468 validates at most 10,000 photo/engine objects; the synthetic 16,832-image fixture has NOT passed c41 and is NOT an authenticated Viewer inventory. A versioned successor needs a bounded authenticated/paged inventory or equivalent independently verified completeness, count/byte/structure budgets and cross-language canonical vectors. Keep c41/v1's existing limits and behavior; negotiate new protocol/engine capability instead of increasing them globally. Viewer and broker must agree dataset file ID/path/role/disposition/content metadata and authoritative source snapshot identity, trusted selection and immutable revision, attempt/authority/principal/env binding and streaming epoch rechecks.

Generated GCP is deliberately held: its attempt-specific descriptor, original retained GCP file IDs/path/hash and generated bytes/correspondence evidence, object ID, name, media type, size and digest require a separately authenticated bijective mapping and verified substitution evidence. Inventory v2 substitutions and v3 excludedAuto also hold. Implement those only in a separately reviewed version without flattening nested paths or changing custody. Avoid interpreting basename uniqueness as an inventory constraint: it is currently a materialization limitation of the page prototype.

The local `tests.test_paged_inventory_link_candidate` fixture compares 16,832 hypothetical source records and tests missing, extra, swapped and boundary mapping; false pins, attempts, altered metadata and generated GCP hold. The fixture contains no actual image data and does not test Viewer authorization, network transfer, disk or restart.
