# Provisional input-v2 budget planner

This source-only calculator is not registered as an API, is not enabled in the driver, and leaves v1 unchanged. Its numbers are an estimate, not a broker grant or evidence of charged or remaining capacity. It does not authenticate the job, verify the supplied manifest hash against the objects, enforce expiry against a clock, reserve capacity, reconcile a lost response, or renew grants. The caller supplies retry allowances; these are not safety guarantees. Runtime use requires agreed identity, authorization, durable cumulative precharge and unknown-outcome handling across both parties and restarts.

The checked-in example is shared with Viewer and its aggregate outputs match. A provisional raw decoder requires exact compact sorted-key UTF-8 JSON, decimal nonnegative integer tokens without exponent, decimal fraction or negative zero, no duplicate keys, and real UTC dates in years 0001–9999 with millisecond precision. Strings use literal ASCII except mandatory JSON escapes for quote, backslash and controls. The decoder is not wired to any endpoint. Viewer must independently implement and jointly test this exact raw-byte policy, framing and limits before interoperability is claimed. No digest of the proposal is defined here.

The current estimate counts one request for an empty object and one per range for other objects; adds caller-supplied retries capped at twice the base request count and twice the input bytes; and rejects totals outside the JavaScript safe integer range. It supports up to 32,768 objects in this isolated planner, but this does not lift the v1 runtime's 10,000-object or metadata limits.
