## Authorization, archive and dependency proof

A root-private600 single-link authorization file has a separately reviewed SHA, operation/authority/node/Engine/container/image, Viewer task generation, native UUID and job identity. It must record the already durable coordinator archive digest, the complete reviewed final inventory (archive path + local path + bytes + SHA), no future cache consumers and the owned maintenance plan/gate generation. The observer rechecks authenticated authority/job/owned-schedule receipt and current stopped state at each destructive phase. It does not invent authority from an old delivery ACK or a bare declaration; the private authorization receipt must be issued/reviewed by the actual controller after capture.

The helper rehashes the complete native archive, reads EVERY file to EOF for full CRC and member SHA, and requires exact equality with the complete final inventory. Every local final file is also rehashed. No10k archive-entry cap or processing/photo-size cap is introduced; ZIP entries are not photo count. Buffers are1MiB. ZipFile central-directory metadata remains proportional to entries; an external bounded runner must hold the operation on resource failure rather than automatically reopen. Large archive verification can take minutes; root independently verified Tim26.2GB and M4E52.3GB, but those observations are not this helper's admission receipts.

Resource closure includes OBJ/MTL, GLTF, GLB JSON chunks, VRT/PLY external resources, B3DM/I3DM/PNTS/CMPT containers and JSON URI/url/schemaUri references in explicit3DTiles manifests. References must remain inside the complete verified inventory, never selected caches. Unsupported extensions/implicit tiles/containers hold cleanup. Geometry/texture BIN payloads are sought over, not buffered. Dependency JSON has a documented32MiB per-object bound and nested composite depth32; exceeding those holds CLEANUP for review, not processing/job eligibility. Actual ordinary GLB and explicit NodeODM tiles are supported; the negative fixtures include GLB and tileset references into cache.

Unknown final suffixes are never assumed dependency-free (including WRL/VRML). The explicit leaf allowlist is PNG/JPEG/TIFF/LAS/LAZ with matching magic, opaque glTF/EPT BIN payloads, UTF-8 non-container TXT/LOG/CSV/PRJ/WKT/BOUNDS records, and restricted PDF reports. PDF must have a standard header/end marker; escaped PDF names are decoded and external-file/action features and compressed object streams hold cleanup. This is deliberately a constrained inspector, not a general PDF parser. Text/PDF inspection uses the same 32MiB metadata budget. Unsupported final formats remain intact and block cleanup for review; they do not block job processing or result import. A renamed binary/container or invalid leaf header also holds.

Real-data read-only compatibility observations from root found standard PDF `/F` annotation flags and `CESIUM_RTC` in both existing final GLBs. Direct unsigned 32-bit PDF F integers are now distinguished from file strings/dictionaries/indirect references; PDF whitespace/comments and escaped names are inspected conservatively. Other external-resource and object-stream guards remain. CESIUM_RTC is admitted only as an exact `center` property containing three finite non-boolean numbers, without additional extension properties. No geometry payload is loaded. Primary format references: [Adobe PDF reference, annotations and file specifications](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.7old.pdf) and [Khronos CESIUM_RTC schema](https://github.com/KhronosGroup/glTF/blob/main/extensions/1.0/Vendor/CESIUM_RTC/README.md). Synthetic fixtures contain representative structures only; no client payload enters Git. These changes still require bounded remote tests and renewed actual-output read-only compatibility verification before cleanup.

The initial raw PDF name scan incorrectly interpreted compressed stream bytes as names; it is replaced by structural classic-xref inspection. Xref offsets/generations select real indirect objects; literal/hex strings and comments are skipped as values, and stream payloads are skipped by exact resolved Length rather than by searching for endstream inside binary data. Annotation F is accepted only in an Annot dictionary and only after resolving a valid unsigned flags integer. All xref objects/references are checked; unsupported external-file/action dictionaries, encryption, hybrid/xref/object streams, malformed boundaries, cycles and unsupported structures hold. Bounds are 32MiB PDF bytes, 2M parsed tokens, depth64, 32 xref revisions and 200K entries per subsection; these are cleanup-inspection holds, not processing admission limits. The structural fixtures include fake external names inside binary payloads/comments/literal strings, actual external filespec refs with escaped names, indirect Length, and malformed stream boundaries. No PDF is rendered or decompressed.

PDF FS file-specification keys (including FileAttachment literal/indirect strings and escaped names) always hold. BIN is not an unconditional leaf: glTF/3DTiles container magic is parsed even when renamed to .bin. Raw BIN requires an inspected glTF buffers[].uri role and must not also be used as tile/image/other resource content. Dependency roles are collected before raw buffers are admitted. Unknown/unreferenced binaries and unreviewed EPT raw-binary layouts hold; ordinary EPT LAZ remains supported. This supersedes the broader opaque glTF/EPT BIN description above. Synthetic ZIP fixtures cover tileset->renamed GLB->cache, untyped tile BIN refusal and legitimate raw glTF buffers.

## Filesystem transaction and recovery

Dirfd/O_NOFOLLOW traversal, same-device and owner checks, no symlink/special-file cache entries and no hardlinked files protect originals. Parent/task/cache inode identities are checked. renameat2(RENAME_NOREPLACE) moves only a selected directory into private700 per-operation quarantine; changed or ambiguous objects are retained. A private600 SQLite FULL journal binds exact operation/auth/prepared-plan digests and records intent/quarantined/erasing/done. File/directory removal stays below the selected private quarantine, checks known inode identities, and fsyncs affected parents. Partial exception/process-loss resumes reconcile source/quarantine identities; unknown states or a recreated source directory HOLD. Completed repeated apply does not touch a new cache.

No result/original copy, DB backup restore, task removal, broad Docker prune or metadata deletion is performed. If any action or outcome is uncertain, leave the engine stopped, node admission held and ingress closed; never auto-reopen. The integration controller owns safe restart/health/resume after exact verification.
