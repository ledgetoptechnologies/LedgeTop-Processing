# Inventory diagnostics and status candidate

When an ordered node inventory is configured, `GET /v2/nodes`, `GET /v2/options`, and `POST /v2/plan` expose the inventory-aware diagnostic contract. A plan returns `decision: node` and `nodeId`, or `decision: wait`; it is an advisory snapshot, does not reserve a slot, and can change before a claim. The existing v1 diagnostic endpoints return `503 use_inventory_v2` in inventory mode instead of changing their documented `local`/`main` decision contract. V2 endpoints return 404 without inventory configuration.

Node health is a best-effort ODM probe. For a TreeDar-only node it is explicitly reported as `health_probe_unsupported`; that does not mean TreeDar is unhealthy. Client-visible task status stays queued until the selected engine reports processing; the execution slot is owned already during submission. Held tasks use the nonterminal queued code with a separate hold marker, even if they were known to have started before the hold. Output and progress come from that task's bound engine while reachable.

The inventory host identifier is operator-supplied, not proof of physical identity or a fence against other coordinators or direct engine access. Existing-state migration requires an explicit legacy host mapping preserving the prior local photo cap; a different fresh state directory cannot itself prove an older installation does not exist. This candidate is not deployed or a production release qualification.
