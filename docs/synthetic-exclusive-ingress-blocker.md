# Synthetic exclusive engine ingress: blocked integration

The existing host ingress (`ops/node_ingress.py`) is a network allowlist and drain proxy. It does not authenticate a job, inspect NodeGate, or authorize individual mutations. The Viewer synthetic submission calls `NativeEngine` directly while `ViewerNodeInputs._gate()` holds the exclusive NodeGate flock. A separate gateway cannot acquire that lock concurrently. Inspecting gate state without the lock or accepting a long-lived token would introduce a reservation-change race. A Docker network configuration alone cannot repair the missing authorization path.

A future isolated test needs a worker-facing internal network and a distinct engine-facing internal network; only the gateway joins both. The engine has no published host port, the worker joins only the worker-facing network, and neither gets a Docker socket, host networking, privileged mode or host namespace access. These are fixture requirements, not a guarantee against a Docker or host administrator. Network topology must be inspected using exact owned container and network identities, and exercised with a negative direct-connect attempt from the worker.

Before such a topology can be a meaningful exclusive-ingress test, the submission and gateway must agree on a lock ownership protocol. One possible design is a gateway-owned NodeGate reservation, with an authenticated, task-bound, operation-specific request whose authorization remains held through upstream forwarding. It must serialize each mutation with gate handover and cancellation, fail closed after interruption, and prevent replay of uncertain initialization, upload and commit. This is a design candidate only; it is not implemented or approved. An alternative is a single process that owns both gate and gateway, provided process lifecycle and independent caller identity are proved. Neither approach can be emulated by checking the gate once then forwarding later.

A qualifying synthetic test must use isolated containers, actual gateway and actual NodeGate authority, verify wrong identity/reservation and concurrent competing calls fail before upstream mutation, inject lock loss and process death, and verify retained data. It must show direct engine access fails from the worker and only gateway traffic reaches the engine. The current code has no gateway implementing this contract, and the only existing loopback engine check accepts a real engine. No production or staging integration is enabled by this document.

A separate `SyntheticGateRpc` experiment now holds the actual gate lock for the server lifetime and accepts a fixed authenticated, job-bound `initialize` request over an already-connected Unix socket. It reaches only a same-process `NativeNodeFixture`; an exclusive fsynced intent marker forbids replay after any uncertainty. Tests cover missing/wrong gate identity, wrong token/job/operation, concurrent request rejection and retry after an uncertain call. This is a single-operation fixture, not a listener, worker integration, coordinator authorization, completed-submission journal, Docker topology, physical network fence or restart/kill proof. The fixture shares a host namespace with its clients; other local callers may reach it directly. Same-UID/host/Docker administrators and external gate-file changes are not fenced. It must not be deployed.
