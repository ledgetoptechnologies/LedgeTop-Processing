# Paged frame receiver candidate (inactive)

This is a non-mounted prototype for a dedicated synthetic SQLite database. It does not authenticate a Viewer, verify that its caller's binding is authoritative, connect a transport, allocate processing work or authorize cleanup. Its output remains `held_authenticated_source_unavailable`. The caller must supply an independently authenticated immutable binding/pin and decoded processing closure/pages, and keep inputs exclusively owned. No such production trusted loader or bounded network transport is implemented.

`initialize` creates candidate-only `candidate_frame_receipts(stage_id,binding_pin,binding_json,closure_json)` and `candidate_frame_pages(stage_id,kind,ordinal,wire)` tables. `stage` checks the source/selected binding identity and count/page-hash fields, requires persistent SQLite journal mode and `synchronous=FULL` or stronger on its connection, and performs one `BEGIN IMMEDIATE` transaction. It inserts canonical processing pages and reads each source/selected frame with a bounded read, preflights JSON, verifies its domain-separated independently pinned page hash, and stages the wire bytes. Before committing it streams staged rows back through the existing held selected-frame verifier, which compares Viewer-style input hash, selected order, GCP source references, processing-page closure, counts and binding. An interrupted, oversized, malformed, pin-mismatched or failed verification transaction rolls back all rows.

On replay after reopening, a matching stage ID/binding/closure rechecks bounded stored page sizes, reloads processing pages, and re-verifies both persisted streams; a changed binding or corrupt stored page holds. An existing verified stage is replayed rather than accepting replacement input. SQLite durability settings are a precondition, not proof that the filesystem or hardware correctly persists flushes. Database owner, file identity, schema installation/migration, external writer fencing, multi-process upgrades, journal recovery under actual power loss, secure source provenance, epoch checks during stream, retention and staged-row cleanup are not implemented. Never attach this prototype to a live database.

The bounded page reader uses standard `BytesIO`/`BufferedReader`; it bounds reads of compliant local streams, not network admission/timeouts or already allocated caller values. Processing closure/pages and selected objects are in memory under their existing candidate bounds. There is no true resumable byte-range transport: an incomplete transaction is rolled back and retry restarts staging from the source. Completed transaction replay revalidates persisted data. A crash after database commit but before caller sees the response is treated as replay after reopen.

Provisional Viewer object naming (dataset ID for originals and `gcp_<attemptId>` for generated GCP) is not enforced here; namespace disjointness, canonical stable IDs and its versioned wire contract still require review. GCP correspondence digest is not independently verified, nor are source bytes.

Windows paired-required test command: `PAGED_MANIFEST_PAIRED_REQUIRED=1 python -m unittest tests.test_paged_frame_receiver_candidate -q` (set the variable using the shell's syntax). Synthetic 16,832-photo fixture plus LiDAR and generated GCP exercises commit/reopen/replay, truncated-stream rollback/retry, synthetic SQLITE_FULL exception rollback, connection-close interruption/retry, unsafe synchronous setting, and stored-page corruption. It does not simulate hardware disk-full, forced OS process death, power loss, network races, actual Viewer authentication or real image bytes.
