# Closed-on-start admission option (unqualified draft)

`PROCESSING_ADMISSION_START_CLOSED=1` requests a closed coordinator admission barrier before the native Viewer facade is served. It requires `PROCESSING_ADMISSION_DRAIN_ENABLED=1`, a persistent prototype state directory and an operator credential; it refuses a configured reference runtime because that separate API is not covered by this barrier. The environment defaults remain unchanged. The existing `ADMISSION_DRAIN_QUALIFIED = False` startup guard remains in force: ordinary runtime configuration cannot enable this feature until the broader admission mechanism is qualified.

For a new admission table, closed state is initialized in the same SQLite transaction as its schema and authority binding. Existing closed state stays closed. Existing open state refuses closed-on-start rather than silently modifying it. Only the existing authenticated operator transition can reopen the barrier. After an explicit reopen, leaving closed-on-start configured causes the next restart to refuse until the configuration is deliberately changed or the operator closes the barrier again.

The barrier rejects guarded native Viewer mutations and result downloads for both production and staging, and generic new job submissions. The existing queue claim path also checks the barrier, including Viewer scheduler and prototype worker claims. A claim admitted before closure can continue to dispatch after the closure receipt; existing running work, status polling, worker completions, operator actions, and optional background archive capture may still mutate state. This option does not prove quiescence, prevent direct engine access, fence an older coordinator or another host writer, or qualify an upgrade/rollback. A full cutover still requires independently enforced admission routing and writer exclusion, drain/reconciliation of in-flight work, and the existing updater guards. No cleanup, deployment or automatic reopening is introduced.
