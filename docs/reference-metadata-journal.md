# Metadata request transition model (inactive)

`processing/reference_metadata_journal.py` implements local semantic matching and a bounded immutable transition model for the proposed metadata addendum. It does not create a durable journal, contact an issuer, allocate disk, authenticate a response or change any runtime path. The original context is a closed candidate intent, finite policy, independently supplied expected actor binding hash, and closed payload-ledger snapshot. These inputs are model evidence, never proof of a real claim, custody, actor or capacity reservation.

The source intent is pinned once for exactly one original parent/stage/purpose. Original acquisition/custody identities, source objects, transfer digest, payload ledger identity/revision and expiry/byte totals remain unchanged. Original objects have unique sorted IDs, exact acquisition binding, and distinct receipt roles. Payload totals must balance and stay within the cumulative three-times-original bound. Already-expired original payload snapshots can be represented without extending their expiry or permitting any payload read.

`prepare` creates in-memory prepared bytes. `transition` records an issue attempt, unknown outcome, same-operation metadata lookup or unverified response. An issue cannot be replayed because the actual issuer's same-key replay contract is not agreed. Lookup is a local record only, never a network request. One attempt must leave issued state before another can begin. Attempts, record counts, exact serialized bytes and a conservative per-attempt maximum-response envelope are finite and recomputed. This envelope is not an actual disk/control charge. There are no paths or storage constructors in this API.

Every response must match all shared original request fields, original source subset and expected actor-binding hash. Matching that hash does not authenticate the actor. Checked time must fall between the original request and the explicitly observed time (no clock-skew allowance is inferred), positive metadata must still be within the policy's at-most-300-second window, and observed time cannot regress or precede the original request. Caller timestamps establish no trusted issuer clock. Custody/revocation revisions cannot regress; the proposed unavailable-denial zero observations never lower the retained highwater. A response receipt cannot change bytes or acquire another identity within the same operation.

A matching positive or denial remains `response_observed_unverified`. Neither resolves an unknown operation, allows another round, grants engine/publication permission nor establishes current source authority. `currentAuthority` is always null. Beginning a lookup clears the latest unverified observation before any subsequent result, preserving old evidence in history without a last-green fallback. No verified-resolution function or caller-boolean bypass exists. A future legitimately resolved next round requires an authenticated issuer integration; it cannot be manufactured by replacing the original context.

`restore` receives the original intent/policy/payload snapshot/actor hash independently and replays every event, revalidating original bindings, transitions, time, counters and budgets. It rejects injected authority and changed summaries. Ordinary `transition` revalidates against the context inside its model; only `restore` takes independently supplied original inputs. Neither authenticates those caller inputs. An attacker who can replace consistent events and recompute summaries is outside this model; it is not tamper-proof history. Serialization/replay is not durable storage, authenticated persistence, a receipt MAC or rollback protection: an older internally consistent snapshot cannot be detected without a real authoritative owner store. Persisting these bytes on actual worker paths is not authorized by this model. Existing bounded candidate-schema loading is reused; subsequent transitions have no payload, network or file-write operations.

Still required before runtime use:

- An agreed issuer issue/lookup/idempotence wire contract, dedicated authenticated actor channel and verification receipt interface.
- Actual immutable original-source custody and purge protection, revocation policy and trusted time observations.
- Exact mapping from real original claim, grant/transfer and cumulative payload ledger to these candidate records.
- A compatible typed metadata control-capacity descriptor and durable owner store with leases, crash recovery, global physical accounting and rollback protection. Existing one-purpose recovery control charges cannot be reused or overwritten.
- An authenticated resolution transition for later rounds, plus engine-admission and historical sealed-output/publication integrations. Sealed outputs must remain retained during outages; this model does not settle, release, clean or emit results.

Tests use explicitly synthetic candidate records, an expired synthetic original payload snapshot and in-memory serialization. They exercise schema-valid parent/source/claim/ledger/purpose mismatches, original object identity and ordering, receipt-role aliases, source totals, changed scope, unknown reply replay, direct construction and counter tampering, lookup invalidation, attempt/history bounds and time/freshness checks. No entire deferred semantic/authentication/archive suite is claimed passed. Actual issuer authority, physical custody, durable crash recovery and production renewal remain unqualified.
