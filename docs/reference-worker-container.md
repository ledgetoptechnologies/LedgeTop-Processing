# Canonical ODM worker container (local source package)

`Dockerfile.reference-worker` packages the existing canonical entrypoint:
`python -m ops.reference_worker_daemon --config <owner-private.json>`.
It uses the coordinator's identical digest-pinned Python 3.13 Bookworm base,
all Processing Python modules, and exactly the two required ops modules:
`reference_worker_daemon.py` and `private_worker_directory.py`. `ops` remains a
Python namespace package; no alternate controller, wrapper or business code is
introduced. The Dockerfile-specific allowlist preserves the coordinator's
existing `.dockerignore` and excludes datasets, tests, config, credentials,
engine checkouts, generated bytecode and unrelated ops scripts. Build from a
reviewed source snapshot and reject symlinked/nonregular selected source files
before building. Record every selected file's exact bytes and the resulting
image ID; a Git revision alone does not identify uncommitted source.

```sh
docker build --pull=false --network=none -f Dockerfile.reference-worker \
  -t ledgetop-processing-reference-worker:local-review .
```

This is a local build, not package publication or installed acceptance. Use the
recorded immutable `sha256:...` image ID for qualification and any later approved
activation. No registry or token is needed at runtime for a locally loaded image.
The process runs as UID1000:GID1000, matching the deployed canonical gates. It
needs neither a Docker executable nor the Docker socket for ODM-only work.
No engine/monitoring/updater service is replaced by building the image.

## Explicit owner-controlled runtime assembly

The following is an **unexecuted Linux activation template**, with illustrative
local host paths only. It requires reviewed real configuration, TLS, identities,
capacity and mounts before use. Do not substitute production secrets or paths
into a shared transcript. No TrueNAS action is part of this host-worker recipe.

```sh
docker run --name ledgetop-reference-worker --init --read-only \
  --network host --cap-drop ALL --security-opt no-new-privileges \
  --stop-timeout -1 \
  --mount type=bind,src=/OWNER/private-worker-config,dst=/run/ledgetop-worker,readonly \
  --mount type=bind,src=/OWNER/private-worker-state,dst=/var/lib/ledgetop-worker/state \
  --mount type=bind,src=/OWNER/private-worker-scratch,dst=/var/lib/ledgetop-worker/scratch \
  --mount type=bind,src=/OWNER/existing-node-gates,dst=/var/lib/ledgetop-gates/LedgeTop-Processing/node-gates \
  sha256:REVIEWED_IMMUTABLE_IMAGE_ID \
  --config /run/ledgetop-worker/worker.json
```

Use literal absolute existing host directories with real UID1000 ownership and
private mode0700 for state, scratch and the existing gate directory; private
config/server key must satisfy the existing owner/private-file checks. Preserve
existing paths and permissions: this image does not repair ownership or provision
host directories. State and scratch mount points baked into the image are
root-owned placeholders, not initialized worker roots. Omitting required mounts
must fail closed under the read-only filesystem. Configuration and TLS are read
only. State, scratch and the canonical gate must survive replacement; do not
use temporary container-private volumes for them. Exact copy retention, disk
budgets, cleanup and read-pin policy remain owned by the existing worker.

For this image `XDG_STATE_HOME=/var/lib/ledgetop-gates`. The actual gate formula is
`$XDG_STATE_HOME/LedgeTop-Processing/node-gates/sha256(engineId)`; an ordinary host
without XDG override uses `$HOME/.local/state` instead. Resolve the **actual host
process's** XDG/HOME and physical Engine ID, then bind its existing `node-gates`
parent into the destination shown above. Independently compare existing inode,
authority, node, generation and reservation state before activation. Never
provision a second container-private gate or change its namespace to bypass a
held reservation. Matching UID alone does not prove host/container gate identity.

Linux host networking is explicit because the existing factory admits only a
literal-loopback native engine origin; container bridge loopback would name a
different machine namespace. Do not publish new engine ports or mount Docker's
socket. Bind the configured result TLS listener to the reviewed private host
address, not implicitly every interface; scope reachability with the existing
host network policy. Confirm the selected physical native backend's CID/image,
recipe, port and actual engine version, the sole worker owner, real coordinator
and broker origins and separate worker/result-reader bearer roles. The image's
configured service identity is not a Docker inspection/admission attestation.
No new credentials, firewall rules or grants are created by this template.

Select only `"serviceProfile":{"schemaVersion":1,"mode":"odm_only"}` for this
qualification. Do not include `executionRouting` or infer TreeDar/combined,
metadata issuer, source custody or Gaussian capability from bundled modules.
The image has no healthcheck containing a secret. Use the authenticated private
`/ltds/worker/v1/health` route externally under the existing result-reader role;
no bearer should be stored in a Dockerfile, label or health command. Liveness
never authorizes new work or result cleanup.

`--check-config` validates private configuration/TLS metadata without opening
worker state, acquiring a gate or starting listeners. Invalid or missing config
must exit nonzero with safe output. The actual configured factory still performs
its independent runtime/backend/ownership checks before it can run.

## Graceful replacement and qualification limits

Drain the node through the single coordinator before stopping the worker.
`STOPSIGNAL SIGTERM` reaches the existing handler (forwarded by `--init`), which
stops new driver work and new result reads, joins active stages/handlers, then
releases only its actual reader/state leases. The example disables Docker's
forced-kill timeout; a stuck or uncertain drain requires investigation, not
permission to kill work or clear a gate. After unexpected process death, retain
all original inputs/results/state and follow the existing stale-reader/claim
reconciliation workflow. Never delete state or manufacture an ACK to restart.
No compute cap is added to the main PC by this recipe.

Local import/help/invalid-config/read-only/UID checks qualify packaging only.
Canonical service tests establish a synthetic TLS/Node/native fixture chain;
`abc` photos and empty ZIPs are not photogrammetry, source provenance or catalog
publication. Actual installed gate/UID/namespace/CID/config/TLS/data-path,
maintenance and restart qualification remain activation gates. This source
package does not deploy Viewer app integration or touch NAS.
